Trusted networks only

The API has no built-in authentication. Run it only inside a trusted Compose project on a trusted network.

Dashboard routes

RoutePurpose
GET /Project overview with CPU, memory, and Compose metadata.
GET /dependenciesService dependency graph.
GET /servicesService inspection and lifecycle controls.
GET /healthzReturns {"status":"ok","version":"0.2.0"} without contacting Docker.

Project metrics

GET /api/dashboard

Returns project metadata, aggregate CPU and memory usage, and resource use grouped by Compose service. Stopped containers do not contribute resource metrics.

{
  "project": {"name": "example-project", "services": 3, "running": 2},
  "resources": {"cpu_percent": 4.25, "memory_percent": 7.32},
  "services": [],
  "updated_at": "2026-08-18T00:00:00+00:00"
}

List containers

GET /api/services

Returns containers in Overseer’s Compose project, excluding Overseer itself. Service names and dependencies come from Compose labels; shared networks do not imply dependencies.

[
  {
    "id": "1234567890ab",
    "name": "web",
    "service": "web",
    "dependencies": ["database", "redis"],
    "status": "running",
    "image": "example/web:latest"
  }
]

Container actions

The following routes accept POST: /api/service/<container_id>/start, /stop, and /restart. Include the CSRF-protection header:

curl --header "X-Overseer-CSRF: 1" \
  --request POST \
  http://localhost:8765/api/service/container-id/restart

Success returns {"success": true}. Missing containers return HTTP 404; Docker daemon failures return HTTP 502.
