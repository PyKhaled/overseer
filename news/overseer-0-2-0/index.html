Overseer 0.2 brings a clearer operational experience.

12 October 20264 minute read

Overseer 0.2 sharpens the project-centric experience: a cleaner operational dashboard, clearer status information, safer action feedback, and a distinctive Sentinel Lens identity.

Logs, events, and alerts

The Project Operations page adds bounded recent and live container logs, project-filtered Docker events, short-retention history, and actions initiated through Overseer. Configurable alerts cover unhealthy containers, exits, restart loops, and resource thresholds, with cooldowns and optional HTTPS webhooks. History is in memory and delivery is best-effort.

A dashboard designed around the project

The refreshed overview puts the state of the full Compose application first. Aggregate CPU and memory usage, service state, and project metadata are easier to scan across desktop and small screens.

One lens for dependencies and controls

The interactive dependency graph remains tied to declared Compose relationships, while dedicated service controls provide safer feedback for start, stop, and restart operations.

A new default port

Breaking change

Overseer now listens on port 8765 instead of 8000. Update Compose mappings, reverse proxies, health checks, and OVERSEER_PORT overrides.

Stronger project foundations

This release adds the Sentinel Lens brand, hosted documentation, and a Make-based development workflow for setup, checks, local serving, image builds, and smoke tests. The repository now focuses on integrating Overseer into an existing Compose project and no longer includes the example stack.
